# 浏览器走查清单

按「**预约两辆车 → 门卫放行 → 调度叫号 → 仓库卸货 → 出场核费 → 承运商提异议**」逐项核对。
每一步都给出**预期页面数字**，最后与下载的 CSV 逐格对账。

> 建议用一个全新库：在 `.env` 中设置 `DB_PASSWORD` 与 `INIT_PASSWORD=dock1234`（仅本地演示用）、
> `SEED_SAMPLE=true`，然后 `docker compose down -v && docker compose up --build`，
> 开两个浏览器（或一个普通窗 + 一个无痕窗）方便切换账号。
> 系统已预置一条**已出场核费样例单**：车牌 `沪A00023`（顺达物流，等待 150 分钟，核费 **60.00 元**），用于核费 / 下载 / 异议的确定性核对。

本地演示初始密码为 `.env` 中设置的 `INIT_PASSWORD`（未设置时取启动日志中随机生成、只打印一次的密码）：

| 角色 | 账号 |
| --- | --- |
| 承运商（顺达物流） | `carrier1` |
| 门卫 | `guard` |
| 调度员 | `dispatcher` |
| 仓库 | `warehouse` |

## 0. 登录与权限（先验证“权限不靠藏按钮”）

- [ ] 未登录访问 http://localhost:8080/ 被跳到登录页。
- [ ] 用 `carrier1` 登录后，浏览器直接访问 http://localhost:8080/gate ，应出现 **403/访问被拒绝**（不是靠菜单藏按钮）。
- [ ] 顶栏只显示该角色该有的入口；退出后换账号登录。
- [ ] 承运商首页看板只见本司车辆与本司核费；直接改 URL 访问别司预约详情返回 **403**。

## 1. 首页看板（任意角色登录即可）

- [ ] 顶部 **6 张月台球**（D1–D6）：D1 显示「卸货中 · 沪A00022」，D2 被已出场样例释放后应为空闲（刷新看实时状态，30 秒自动刷新）。
- [ ] 「今日核费」面板能看到 `沪A00023`，**原始金额 60.00，最终金额 60.00**，合计 **60.00 元 / 1 单**。
- [ ] 顶部北京时间时钟与当前实际北京时间一致。

## 2. 承运商预约两辆车

登录 `carrier1`，进入「新建预约」，连续提交两辆车（车牌自取，如 `走查001`、`走查002`）：

| 字段 | 车 1 | 车 2 |
| --- | --- | --- |
| 订单号 | WALK-A | WALK-B |
| 车牌 | 走查001 | 走查002 |
| 司机 | 张师傅 | 李师傅 |
| 货类 | 常温食品 | 日化百货 |
| 月台类型 | 普通月台 | 普通月台 |
| 日期/时段 | **今天、当前所处的半小时时段** | 同上 |

- [ ] 两单都提交成功，跳详情页，显示**预约码**（形如 `YY26091200xx`），状态「已预约」。
- [ ] 「我的预约」里能看到这两单。
- [ ] **容量拦截（可选验证）**：再连续提交，把当前时段补到第 7 辆时，应被红色错误页拦下，提示「预约容量 6 已满」。
- [ ] **插单（可选验证）**：换 `dispatcher` 登录 → 「调度插单」，不填原因提交应被拒；填写原因（如“客户加急”）后提交成功，详情页永久显示「插单 + 原因 + 操作人」。
- [ ] **费率配置（dispatcher）**：顶栏「费率配置」打开 `/rates`，可见 14 天 × 承运商矩阵，今/明两日已有种子价；把某未来日期改成 120.00 保存后出现成功提示。用非调度账号直接访问该 URL 应返回 **403**。

> 记下两辆车的**预约码**（门卫要用），或保持「我的预约」页开着。

## 3. 门卫放行

登录 `guard`，在「门卫办理进场」：

- [ ] 输入车 1 预约码 → 放行，页面提示车牌与预约码；在「当前在场车辆」看到它，状态「等候中」。
- [ ] 同样放行车 2。
- [ ] **同一预约码再输一次** → 红色错误：「禁止重复进场」。
- [ ] 预约时段内进场，**不**出现迟到/早到红标（若你预约的是当前时段）。
- [ ] 「今日预约」表里两车状态变为「等候中」。

## 4. 调度叫号派台

登录 `dispatcher`，打开「排队叫号」：

- [ ] 等候队列按**进场先后**排序列出两车，并实时显示「已等候 x 分钟」。
- [ ] 月台下拉中，与车辆所需类型不符的月台不可选；对车 1 选一个普通月台（或留「自动分配」）→ 叫号，状态变「已叫号派台」。
- [ ] 对车 2 叫号到**另一个**普通月台；若强行选车 1 已占用的月台（可在另一窗口快速操作），系统提示「已被占用，禁止双占」。
- [ ] 回首页：对应两张月台球变为占用（显示车牌/货类），等待车辆数减少。
- [ ] 已派台的车，「叫号」按钮置灰，重复叫号会被状态校验拒绝。

## 5. 仓库卸货

登录 `warehouse`，在「仓库作业」依次对每辆车操作：

**靠台 → 开始卸货 → 卸货完成 → 出场并核费**

- [ ] 四枚按钮按状态逐个出现，不能跳步（未靠台时没有“开始卸货”）。
- [ ] 「靠台」动作把等待分钟固化；详情页时间线逐步追加，每条都有**操作人（仓管小李）与北京时间**。
- [ ] 第二辆车若尝试靠到未分配给自己的月台，被「靠台月台与调度派台不一致」拒绝。
- [ ] 两车出场后，首页对应月台球恢复「空闲」。

## 6. 出场核费与下载对账

- [ ] 打开车 1 / 车 2 详情页：因为连续操作，等待一般只有几分钟，**免费分钟 90、计费分钟 0、原始/最终金额 0.00**。
- [ ] 打开样例单 `沪A00023` 详情页（或在首页「今日核费」点车牌）：
  - 等待 **150** 分钟、免费 **90**、计费 **60** 分钟；
  - 原始金额 **60.00**，最终金额 **60.00**（费率 60 元/时 × 1 小时）。
- [ ] 点首页右上「**下载当天核费明细 CSV**」（Excel 直接打开不乱码），逐格核对：
  - 表头含：预约码、承运商、车牌、等待分钟、免费分钟、计费分钟、**原始金额、最终金额、核费状态、费率分段快照**；
  - `沪A00023` 一行：等待 `150`、免费 `90`、计费 `60`、原始 `60.00`、最终 `60.00`；
  - 你刚走的两车：计费 `0`、金额 `0.00`；
  - CSV 各行最终金额合计 = 首页「今日核费最终金额合计」。

## 7. 承运商提异议 → 调度处理（原金额不许被抹掉）

登录 `carrier1`（顺达物流，即样例单所属承运商）：

- [ ] 打开 `沪A00023` 详情页，底部填异议原因（如“等待系月台故障，非我司责任”）→ 提交。
- [ ] 详情页出现异议记录「待处理」，核费状态变 `DISPUTED`；**原始金额仍显示 60.00**。
- [ ] 换 `carrier2` 登录尝试对该单提异议 → 被拒（只能对本承运商的单）。

登录 `dispatcher` → 「异议处理」：

- [ ] 列表显示该异议与**原始金额 60.00**。
- [ ] 场景 A（本清单走这个）：「成立并调整」填 **30.00**，说明“园区承担一半” → 提交。
- [ ] 回详情页核对（关键）：
  - **原始金额 60.00 仍在**，最终金额变为 **30.00**，状态 `ADJUSTED`；
  - 异议记录同时保留原金额 60.00 与调整为 30.00、处理说明、处理人、处理时间。
- [ ] 重新下载 CSV：`沪A00023` 一行原始 `60.00`、最终 `30.00`、状态 `ADJUSTED`；
  首页合计随之变为 **30.00 元**（最终金额口径），但原始 60.00 在页面和 CSV 中都还能对上。
- [ ] 该异议在处理页消失（已处理不可再改）；直接重复提交处理接口会被「已处理，不能重复处理或覆盖结论」拒绝。
- [ ] 场景 B（可选，再提一条异议后走「驳回」）：最终金额维持不变，状态 `UPHELD`。

## 8. 月台保养停用（设备科半天保养）

设备科通知 **5 号冷藏月台（D5）明天 08:00–12:00 保养**。D5 是唯一冷藏月台，停用期间该时段冷藏容量归零。

1. 用 `carrier2`（冷鲜运输，冷藏）在「新建预约」里给明天 **09:00、09:30** 各约一辆冷藏车
   （车牌如 `保养001`、`保养002`），再给明天 **14:00** 约一辆（`保养003`，用于对照窗外不受影响）。
2. 登录 `dispatcher` → 顶栏「月台保养」（`/maintenance`）：

- [ ] 登记：月台选 `D5 · 5号冷藏月台（冷藏月台）`、日期明天、开始 08:00、结束 12:00、
      原因“设备科半天例行保养”→ 提交后进入停用详情。
- [ ] **受影响清单恰好列出保养001、保养002 两单**；14:00 的保养003与普通月台类型的单**不在**清单内。
- [ ] 停用登记后，`carrier2` 再约明天 10:00 的冷藏单被红色错误拦下：「没有可用的冷藏月台（月台保养停用）」；
      调度插单同样被拒（无台可派）；普通月台照常可约（容量 4 = D1–D4）。
- [ ] **第 1 单（保养001）**填待定原因 →「改约待定」：该单进入「处置记录」，状态变「改约待定」；
      用 `guard` 扫它的预约码 → 被拒：“已标记改约待定，请联系调度员确认新时段后再进场”。
- [ ] **第 2 单（保养002）**选明天 **14:00**、填改期原因 →「改期到此时段」：
      清单中该单消失，处置记录显示 **原时段 → 14:00**；
      打开该预约详情：车牌/订单/货类/预约码均未变，底部「月台保养改期记录」保留原时段、原因、操作人与时间，
      操作时间线多一条「月台停用改期」。
- [ ] 把目标槽约满后再改期（如 D5 保养时把唯一冷藏容量占掉）→ 被拒：「容量 1 已满」；
      第 1 单再改期到明天 **15:00** 成功（待定 → 已预约）。
- [ ] 固定在停用时段内看**首页看板**：D5 球为**红色顶边 + 🔧 保养中 08:00–12:00**，与绿色空闲、琥珀占用一眼分开；
      普通车自动叫号派台不会派到停用月台（手选 D5 报“保养停用中”）。
- [ ] 在停用详情填原因「保养提前完成」→「取消停用」：D5 容量恢复为 1，首页红色标识消失。

对应自动化测试：`MaintenanceWalkthroughTest`（清单准确性、待定释放容量/禁入、改期原值留档、
容量拦截、看板标识、派台跳过停用台、取消恢复）。

from operation_event where appointment_id =
